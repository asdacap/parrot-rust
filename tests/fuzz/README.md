## Seeds, budgets and reproducibility

`../fixtures/regressions/T77/campaign.json` is the committed source of seeds and
case counts. The exact SplitMix64 implementation is `generator.rs`, shared with
the actual TaskScheduler test. Domain generators reset independently for all three
seeds. Cases have a stable zero-based index and include input and trace context in
failures. Each domain executes fixed malformed, duplicate, and boundary
regressions before its seeded cases. The independent source-history
duplicate-policy test is unconditional.

- Nine format surfaces: YAML, task JSON, persisted and operational queue JSONL,
  derived history JSON, generated protobuf, SSE, Responses WebSocket messages,
  terminal bytes, and lexical paths.
- Generated binary probes are at most 512 bytes. Text atoms are at most 48. Queue
  models perform 32 operations per case. These are **harness budgets**, not
  invented product size or depth limits.
- Real boundaries include task descriptions of 300 UTF16 units, task JSON depth
  64, a 16MiB queue read and encode, SSE UTF16 line accounting, WebSocket limits
  of 16MiB per request, 4MiB per event, and 64MiB per stream, and a terminal paste
  of 65536 raw bytes.
- Actual lifecycle and barrier tests use five-second failure deadlines. The actual
  host fixture has its existing bounded deadline. No timed-out case is caught and
  retried into success.
- Queue close stress has at most 8 participants including the closer. Seeded
  launch order is recorded, but the OS may choose different legal mutex
  acquisition order. Assertions account for every accepted item and reject
  unsupported global-order promises.
- Broker replay loading uses a controlled synthetic persistence vector. It proves
  actual broker subscribe, replay, and live policy, not SQLite durability.
  Lifecycle tests use a controlled backend. They prove actual session ownership
  and single-drain behavior, not provider or database persistence. The separate
  TaskScheduler cases use actual store, scope, scheduler, child, and close owners
  with deterministic provider gates and deny-external profiles.

## Required caller lifecycle (T46 / T48)

The source's synchronous filesystem work is adapted to explicit awaited sampling; runtime never blocks on asynchronous I/O or falls back to `std::fs`.

1. Construct the injected read/install services and session security provider, selected resources, templates, `SkillCatalog` and `AgentSkills`. No report or supplied path is an authorization token.
2. `AgentSkillPromptProvider::new(Arc<tokio::sync::Mutex<AgentSkills<...>>>)` is async only to obtain the shared view without blocking.
3. At turn start **await** `AgentSkills::begin_turn`, then `select` with the actual conversation parts. Unknown mentions refresh the catalogue. `render` rereads each selected file with an expected target/1MiB cap, returns full selected instructions and only successfully loaded paths. A failed render retains pending selection; a completed render clears selection but retains turn deduplication.
4. **Await** `SystemPrompt::sample_epoch(cancellation)` at the prompt epoch boundary before `build(selection)`. Static/model products default to existing `renew_epoch`; composite sampling awaits children in key order and stops on failure without pretending to roll back already-sampled children. AGENTS stores a new epoch only after a complete successful sample. An explicit synchronous AGENTS `renew_epoch` invalidates it; it cannot do I/O.
5. Live runtime callers await `SessionPrompt::build(selection, cancellation)` or `capture`; these use `SystemPrompt::build_live` without renewing the epoch. The default delegates to synchronous `build`, and composites await their actual children in order. Skills await the actual `AgentSkills::build_catalog`: the active turn uses its captured snapshot, while outside a turn it captures the catalogue, matching pinned source `SkillPrompt.Build` → `BuildCatalog`. No copied catalogue is retained across `end_turn`, and AGENTS is not resampled by a live build. The lower-level synchronous skill `build` still reads the shared view populated by successful capture/refresh; after `end_turn` clears it, synchronous callers must first await sampling/build_catalog. Rendering failures remain build failures, not unexpected `begin_turn`/`select` failures. Failed/cancelled refresh preserves the previous view, but live callers receive the failure rather than falling back to it. The prompt gate covers only sampling/live construction and the synchronous capture callback, never provider/tool/status/persistence awaits.
6. Await/join `extract_packaged_skills` completely before releasing installer lifetime; source extraction has no cancellation parameter. It is not safe to infer completed mutation from a dropped observer.
7. T48 may retain/derive `PromptScope` and call `apply(identity_description)` before materialization; do not duplicate scope formatting or mistake it for policy attenuation.

## Required caller lifecycle (T46 / T48)

The source's synchronous filesystem work is adapted to explicit awaited sampling; runtime never blocks on asynchronous I/O or falls back to `std::fs`.

1. Construct the injected read/install services and session security provider, selected resources, templates, `SkillCatalog` and `AgentSkills`. No report or supplied path is an authorization token.
2. `AgentSkillPromptProvider::new(Arc<tokio::sync::Mutex<AgentSkills<...>>>)` is async only to obtain the shared view without blocking.
3. At turn start, await `AgentSkills::begin_turn` to capture the catalog. Core queries metadata through `get_skills`, deduplicates returned identities, then requests bodies through `read_skill_content`. Each body read uses current security authority, the record's expected physical target, and a 1 MiB read cap. Native state retains no selected-record list or turn deduplication set. `end_turn` releases only the catalog snapshot and live prompt view.
4. **Await** `SystemPrompt::sample_epoch(cancellation)` at the prompt epoch boundary before `build(selection)`. Static/model products default to existing `renew_epoch`; composite sampling awaits children in key order and stops on failure without pretending to roll back already-sampled children. AGENTS stores raw files for a new epoch only after a complete successful sample. Sampling does not expand templates. An explicit synchronous AGENTS `renew_epoch` invalidates it; it cannot do I/O.
5. Main-request `States` getters acquire raw prompt state through `SessionPrompt`. Core renders supplied literals, template arguments, AGENTS files, model guidance, identity, standing instructions, and skill entries. It retrieves concrete compiled templates through `States::get_config`. Native compaction and live observation use `SessionPrompt::build(selection, cancellation)` or `capture` as shared rendering conveniences. Live source acquisition receives the selected model and cancellation, and composite acquisition awaits each actual child in order. Skills use `AgentSkills::read_catalog`: an active turn uses its captured snapshot, while an idle caller captures the catalog. No copied catalog survives `end_turn`, and a live build does not resample AGENTS. Synchronous rendering reads the raw shared skill view, so callers must sample or acquire it after `end_turn`. Template failures occur during rendering, not materialization, sampling, `begin_turn`, or metadata lookup. Failed or cancelled refresh preserves the previous raw view, but live callers receive the failure rather than stale data. The prompt gate covers sampling, raw acquisition, rendering, and the synchronous capture callback. It never covers provider, tool, status, or persistence awaits.
6. Await/join `extract_packaged_skills` completely before releasing installer lifetime; source extraction has no cancellation parameter. It is not safe to infer completed mutation from a dropped observer.
7. T48 may retain/derive `PromptScope` and call `apply(identity_description)` before materialization; do not duplicate scope formatting or mistake it for policy attenuation.

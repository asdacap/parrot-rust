## Implemented surface

- `ProviderTokenBudget` consumes the actual provider `Completion` and `Model`: selector-local positive input calibration, missing-usage preservation, reset, saturating calibrated estimates, selected-model input limits, default/model output limits and integer five-percent headroom.
- `CompactionPlanner` consumes actual `ProviderModel`, session `Message`/`Content`/`Tool`, `ResolvedModelSelection` and domain `ModelProfiles`. Text estimation reuses domain `TokenEstimator` (UTF-16 length). Images invoke the actual selected provider's `calculate_image_tokens`; image paths/bytes are never read here and no provider/session/credential/catalogue call is made.
- Context estimates preserve total context-window reporting versus input-limit triggering. Alias/context overrides and target budgets use the existing domain `ContextCompactionPolicy`; `plan_selected` connects that resolved policy to the actual planning operation.
- Causal grouping follows source `Groups`: assistant tool calls absorb only immediately following tool messages, preserving order. Completeness uses ordinal tool-call IDs, including source's existence—not cardinality—rule. Ordinary/orphan messages remain separate groups.
- Planning chooses the source checkpoint cut, backs up to the earliest incomplete prefix group, respects the caller's base watermark, resolves actual model-profile input/summary budgets and returns eligible oversized tool-group indices. It never persists a blob or invents its notice text or successful replacement fit. The request estimator accepts actual preceding summary text and chunk tokens for later summary-dependent decisions.
- `ContextCadence` and `RetainedAgentBudget` are the existing domain values re-exported for consumers, not reimplemented services. Their basic interoperability regression is not a new exhaustive cadence/budget parity claim.

`CompactionGroup` borrows actual session messages. A caller may supply actual durable group metadata. `group_messages` instead assigns synthetic positional watermarks exactly like the source's history-only overload; those numbers are **not** repository sequence numbers or persistence proof. The planner trusts the supplied completeness/checkpoint metadata, as the source `CompactionGroup` contract does.

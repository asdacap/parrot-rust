# T45 compaction and context budgets

AI-generated by Parrot, `medium_llm` (GPT-6.1-sol/high), with independently delegated source observations and review. Source pin: `5f27a8a92625ee31d8bec094e5c3e09550193781`.

This module adapts core-owned compaction planning, execution, and fitting to the actual provider, template, storage, image, and T44 prompt interfaces. Native context epochs read owned history data and persist the fitted result. It supersedes the earlier planning-only component, whose exact historical handoff is preserved in [README.budget-planning.md](README.budget-planning.md). It is not a new graph stage or acceptance of the complete application, T46/T53 callers, host/security composition or P15.

## Implemented behavior

- `ProviderTokenBudget` adapts the core token-calibration and output-budget policy to native models and completions. The main request loop and native inline context helpers share the core reminder comparison. Domain `ContextCompactionPolicy`, `ContextSnapshot`, `ContextSize`, `TokenEstimator`, and `RetainedAgentBudget` remain native inputs.
- `CompactionPlanner` supplies native estimates for the complete request, including text, tools, selected-provider image costs, and fixed overhead. It captures raw configuration and adapts native data to core. Core resolves targets and owns checkpoint selection, incomplete-prefix protection, watermark progress, and spill eligibility.
- `Compactor` renders the catalog's summary instructions and prefix, then delegates safe-prefix selection to core. The shared core algorithm assembles and invokes summary requests, chunks complete groups, recursively halves empty-summary folds, checks actual returned-path notice fit, and preserves ordered first-pass and once-only late spills. Native `States` adapters retain real blob persistence, catalog notices, and awaited progress. Native `Provider` adapters supply model-aware estimates and private summaries. The summary collector retains awaited retries, exact completion barriers, and disposal precedence.
- The executor returns summary + fixed status + intact retained groups and verifies the final complete selected-model input limit. Summarized history is not deleted from the authoritative database. Retained content, tool IDs/results, image references and provider-native replay fields are cloned intact.
- `ContextController` reads a raw `AgentHistoryView` snapshot and materializes its flat durable tail. The snapshot atomically captures the previous summary, post-watermark rows, stored tool ownership, status classification, and active checkpoint sequences. Current in-memory messages are separate. Core's `prepare_compaction` directs epoch sampling and lifecycle publication, assembles causal groups, computes completeness and checkpoint flags, and renders initial status. Core's `compact_conversation` owns planning, summary execution, and actual-status fitting. Its fitting loop compares complete context snapshots and allows eight rerenders after the initial rendering. The native status adapter only observes and renders the supplied snapshot. Turn and standalone compaction obtain native mechanisms through `States`, `Provider`, and `EventPublisher`. Core exposes no separate preparation, status, summary, or compaction-effect contracts. The controller commits the fitted snapshot, status, and watermark, resets calibration only after successful persistence, reloads `AgentConversation`, and awaits publication. Native adapters publish started, finished, and failed events, including failure after a terminal-publication error. Public forced `compact` bypasses the trigger but returns unchanged for an unavailable input limit. Direct `compact_epoch` retains source's **unguarded** no-progress estimate-versus-input-limit failure, even for zero or negative capacity.
- `ensure_epoch` and `inject_status` support source pre-promotion ordering. Status-fit estimates include actual next-promotion materialized input parts. Child initial status is injected once; root status uses actual mode/version consumption. `StatusInjection::RefreshSelection` returns ownership to the caller for full profile/model/security refresh before retrying.
- Context reminders compare current usage with the last stored reminder for the same model and context limit. Reminders use 10-percentage-point bands starting at 50%. Committed compaction clears stored reminder checkpoints. No separate reminder tracking state is retained. A candidate reminder crossing the trigger is discarded in favor of actual compaction. Final-provider-request and tool-restoration markers use real projection state and restore once.
- `provider_message` converts actual storage materialization without reading image bytes during estimation. Real image artifact persistence/materialization, provider-request loading, retained images and reopen are exercised. Literal source image-size rows and OpenAI calculator boundaries (56/150 images, 97,048/229,376 image tokens, bounded eight-image chunking) use the actual native calculator.

## Invocation and ownership contract

`Compactor::new(settings, profiles, templates)` renders execution template text; the settings' rendered-text fields remain useful to the independent planner but are overridden by the real catalog for execution. `compact` accepts actual resolved selection, target, `PlanningInput`, **mutable** real `CompactionGroupBlobStore`, shared caller-owned `ProviderSessions`, awaited `CompactionObserver` and cancellation. The facade delegates to `parrot-core::compaction::compact` through `States`, `Provider`, and an explicit caller cancellation token. Core passes that token to summary calls and compaction effects. Core returns concrete protocol errors with typed planning and compaction details. Invocation-scoped native error storage preserves original provider, blob, and history errors at the native API boundary. Failure-publication errors replace earlier errors, preserving cleanup precedence. The observer preserves provider retry notices and reports completed/total conversation groups at successful summary folds, including recursive fallback folds. The controller emits a saving phase before committing the snapshot; start/finish/failure events bracket progress, including no-op completion. No summary text is published as progress.

`ContextController::new(compactor, history, blobs, templates)` owns context-epoch state and calibration. `EpochInput` borrows the existing `parrot_storage::conversation::AgentConversation`, selection/tools, T44 `SystemPrompt`, provider sessions and bound status/event adapters. There is no duplicate conversation model.

T46 awaits each controller and executor future rather than dropping it to cancel. Native initialization owns provider-pool lifetime and turn, profile, and security selection. It ensures the epoch, injects status, refreshes selection when requested, and restores skills and tools before input promotion.

Core's turn entry points accept `States`, `Tools`, `Provider`, `EventPublisher`, and an explicit caller cancellation token. `EventPublisher` owns the prompt-epoch hook and reports compaction start and preparation failure. The hook honors request cancellation. Compaction notifications do not. Core owns tool advertisement phases, oversized-request recovery, and request preparation. `States::get_config` supplies typed configuration selected by `ConfigKey`. Raw state getters expose prompt values without template expansion. Core renders instruction sections, retry messages, and context reminders. It selects reminders using `States::get_last_context_reminder` without separate tracking-state writes. `States::get_exit_blockers` joins mutations and reads native completion sources. Core records the supplied feedback and decides whether to continue.

Core checks a pending prompt's token cost before passing it to `States::record_pending_prompt`. Recording returns a `PromptPublication` only for a new insertion. Core acknowledges the recorded prompt before uncancelled publication through `States::publish_pending_prompt`. Pending prompts and publication receipts remain local values. Only selection and ordered completion-source bindings remain in `TurnBinding`.

For automatic and oversized compaction, `States::read_conversation_state` returns raw conversation data. Core obtains lifecycle notifications through `EventPublisher`, including the awaited `on_epoch_started` hook that refreshes native prompt inputs before rendering. It obtains status, blob, and progress effects through `States`, and model estimates and summaries through `Provider`. Callers do not supply separate compaction preparation services. Standalone native compaction uses those same contracts and shares core planning, execution, and fitting. Recording receives sampled instructions and definitions explicitly, without hidden pending-compaction state.

Preparation failures after a successful start await failed publication before returning without recording. Planning, summary, and fitting failures reach recording before propagation. Native effects hold the runtime-state lock during blob publication, not during summary calls or status fitting. The main adapter does not call `prepare_epoch`. That convenience remains for inline tools and direct native callers. Explicit user compaction calls `compact` through `compact_epoch`.

`ContextError::InvalidOperation` identifies only the four explicit source invalid-operation sites (rendered/final input limit, duplicate snapshot and no safe boundary); `Argument` identifies blank tool-call IDs. Their display text is unchanged. Generic template/adapter `Operation` remains opaque/unexpected; consumers must not infer a diagnostic kind by parsing its message or classify every `Operation` as an invalid operation.

`ContextStatus` is bound by the actual status owner to its agent/profile/selection; it must evaluate the supplied actual-history estimator when fitting. `ContextEvents` distinguishes:

1. `emit(Event, cancellation)`: caller's actual emitter persists the new lifecycle event and publishes after commit.
2. `publish_committed(Committed<Event>, cancellation)`: the controller supplies an attestation **only after** `append_compaction_status(...).await` returned true and the conversation reload completed. The adapter forwards the supplied receipt to the real committed publisher. False/error paths never attest.
3. `publish(Event, cancellation)`: retained publication after projection-only status/reminder/final/restoration effects. Those source operations deliberately do **not** record an Event row. Retained is not durable/replayable; adapters must not invent a commit, append an extra event, downgrade to transient, or infer the route from notice kind.

The owning `RetainedAgentBudget` reservation transitions are literal source-tested here; user-session/registry reservation lifetimes remain T48/T53 composition, not a second budget service in this controller. Summary calls use the supplied actual provider/session decorators; turn usage recording remains the actual T46/provider/statistics owner. No second output accounting is introduced.

## Explicit downstream and release boundaries

The four original UserSession source observations **do not prove Rust session serialization**. T46/T53 must independently exercise: compaction waits for an active provider; queued compaction cancellation emits no compaction events; shutdown cancels queued compaction and rejects later admission; cancelling one running compaction does not cancel the next queued request. T46 also owns actual adapter wiring, once-only oversized retry and all A003 causal/terminal obligations. T48/T53 own retained-agent registry/session lifetimes. Full runtime acceptance remains T54.

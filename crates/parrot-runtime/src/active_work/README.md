## Source semantics retained

Pinned source: `5f27a8a92625ee31d8bec094e5c3e09550193781`, `src/Parrot.Core/Agent/ExitReminder.cs`.

- Constructor replays only this agent's `exit_reminder_changed` notices, in recorded order. Each change removes the prior title; a description oneof appends at the end, while cleared/absent state removes.
- Live Set replaces in place; therefore an updated title can have a different position after rehydration. Titles are returned as an owned snapshot.
- Identical Set still appends/publishes but does not reset the render count. New/changed descriptions and successful-found Clear reset it. Missing Clear does neither.
- Empty titles error at append; whitespace is literal. Rust strings cannot represent source null arguments.
- Source empty-description quirk is retained: Set keeps a live empty-description entry, but its durable wire change is `cleared=true`, so a new instance omits it. Manually recorded description-oneof empty text still rehydrates as present; `cleared=false` is still a cleared oneof, not a description.
- First/nth rendering uses actual configured templates, literal title/description text, original teen/last-digit ordinal rules and the source's signed unchecked counter wrapping. Count changes precede render errors.
- Malformed changed-notice protobuf is an observable constructor error, not ignored recovery.

## Runtime API and composition

`RuntimeBackend<S, T>::new(RuntimeConfig<S, T>)` asynchronously builds a real
history/provider backend; `AgentSession<RuntimeBackend<S, T>>` supplies the
session-owned drain. It is not another repository, compactor, activity tracker,
provider implementation or settlement engine.

| Module | Responsibility |
| --- | --- |
| `lifecycle.rs` | One owned drain, admission/wake, FIFO executions, incoming-input wait, scheduled work, retained mutation lifetimes, interrupt/resume and joined shutdown; domain execution/status/drain-state types. |
| `engine.rs` | Actual durable conversation and provider-session orchestration, awaited T44 prompt/skills and T45 controller, supplied completion callbacks. |
| `provider_call.rs` | Consume the genuine injected stream to EOF, batch fragments, record completions, phases/retries and awaited close. |
| `budget.rs` | Request/final-phase budget and four settlement extensions, separate from T45 token budgeting. |
| `usage.rs` | Actual repository request/tool facts, replay-seeded live statistics and retained notifications. |
| `services.rs` | Required injected contracts, captured selection, borrowed resources and typed errors; no successful default host. |
| `activity.rs` | `LiveActivity` adapts the existing domain tracker and safe `TurnDiagnostics`. |

`RuntimeConfig` requires a matching identity/bound history; broker and committed
publisher; model/profile/security selection and tool adapter; prompt, skills,
controller and status binding; ordered callbacks; templates; an **already
constructed shared** `Arc<ExitReminders<Publisher>>`; output, activity, parent
delivery, authoritative immediate-parent-to-root statistics handles and IDs.
It does not replace a reminder instance captured by callbacks or construct a
filesystem/security backend. Required output close and parent/activity hooks
remain explicit even when an embedding chooses no-op policies.

`TurnSelection<S>` owns a resolved model/profile and immutable `Arc<S>` snapshot.
Exact-name allow/disabled filtering is ordinal, not authority parsed from display
text. `TurnTools::Snapshot` is a concrete owner-chosen retained type, not a
names-only reconstructed catalog. Actual budget/profile tests assert one
materialization, per-request ordinal filtering, a captured profile during the
turn, injected survivor-only final tools and current selection/restoration on
the next queued turn. Their inert `Security` and cloned definitions are not
production tool-object identity or fresh per-invocation authority proof.

## Ordering, lifetimes and diagnostics

Actual admission commits before publication/wake; duplicate sends can wake
surviving pending input. A new turn captures selection, begins the request budget
and provider turn, durably emits `TurnStarted`, awaits epoch preparation, injects
status/recaptures selection if requested, begins skills/restores tools and then
promotes input. Steers promote together; one queue input promotes only with no
steer and a nonanswerable conversation. Nonempty selected skill context follows
its input in the implementation. The added bounded nonempty rendering fixture
now proves exact body/steer/new-turn history and content-free event/path ordering
without rerunning T44 discovery/parsing/security algorithms.

The lifecycle owns its drain independently of unary observers. FIFO reservations
include predecessor callbacks; cancelled reservations retain position. Incoming
waits have one reader registration. Settlement repeatedly joins accepted
mutation lifetimes and rechecks wake/scheduled/durable input under the admission
gate, including work accepted after a prior snapshot. Real tests hold an admitted
reminder behind SQLite and admit another after the second terminal snapshot:
dropped observers cannot release drain completion early or lose rehydratable
state. Handled cancelled publication returns typed cancellation to the operation
observer but leaves committed reminder state and the current provider turn
successful. Invocation `Err` belongs to its observer; true task panic/join failure
remains cleanup failure. `is_active` includes unfinished accepted mutations.

`LifecycleError::{Cancelled, ShuttingDown, Failed}` and context/planning errors
retain types, never inferred from display text. `begin_turn` resets only request
count; callback `restart` resets all budget state. Final callbacks prove source
order/short circuit, per-attempt candidate IDs and the two-request/budget2 reset
without a second-request final notice. `length` with tool calls and invalid JSON
are discarded before batch persistence/count; any valid JSON value is accepted.
Actual repeated-truncation/no-tool-length and six-request extension-runaway
branches now have focused durable-drain proofs. Batch count/order is accepted
by HIGH as direct `len()` plus awaited emit-before-reconcile composition, not a
new mandatory three-call campaign.

`ProviderCall::stream` consumes to EOF and returns the full last Completed event.
It batches source-stream text/reasoning and flushes a held suffix at500ms even
while next-read stalls, without detaching/restarting it. Retry flushes/reset
phases; empty data does not clear headers. Cleanup flushes and stream close are
awaited on cancellation/error, including storage/publication/output/usage errors.
Actual close gates also prove provider-pool then output shutdown are joined.

`SessionUsageRecorder` persists only request/tool facts through actual
`record_usage`, applies replay-seeded authoritative own/ancestor statistics after
append and retains live notifications without forging durability. Own,
cumulative and context values stay distinct; cached-price presence, raw negative
usage and effort identity are preserved. No `AgentStatisticsUpdated` is added to
durable replay.

`RuntimeBackend::listen(cursor, capture_scopes)` delegates T43 lazy repository
replay, then supplied scope snapshots and actual usage snapshot. The algorithm
is a thin inspected composition accepted by HIGH together with T43 real-store
no-gap/overlap, slow-replay/fresh-capture, failure and cancelled-observation tests
and actual usage snapshot/replay tests. No duplicate broker suite or mandatory
wrapper smoke test is required for R12.

Real `LiveActivity`/manual-clock tests assert1234ms execution/provider timing,
`AgentFinished.elapsed_ms`, terminal outcome and terminal publication → tracker
finish → parent delivery. `AgentFailed` has no elapsed field. Each started turn
has one matching diagnostic finish for normal, postcommit publication cancel,
provider failure and max0 runaway. Diagnostics receive safe outcome/code only.
`TurnFailed` uses the actual **top-level** provider `response_body()`; no nested
causewalk leaks raw bodies. Typed prompt, summary-provider and retry-publication
cancellation produce interrupted/no-failure endings and awaited cleanup. Exact
`ContextError::InvalidOperation`/`Argument` and `PlanningError` classifications
remain typed; mixed opaque `Operation` is not blanket invalid-operation.

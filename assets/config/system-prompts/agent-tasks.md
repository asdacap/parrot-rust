## Agent Tasks
AgentTasks form a dependency graph. Tasks receive payloads and dependency results, and return results to dependents or as the graph's final result. A composite contains child tasks; a leaf does not.
A composite task passes its full inner task list to the child prompt rather than automatically registering it. The child is expected to double check the list of tasks uses set_agent_tasks to declare and manage its own graph, meaning the inner tasks is a suggestion. The composite task agent supervises the children, modifies child tasks if needed, and validates the outcome once they are resolved. If it is incomplete, the agent may retry with a modified payload, or break down the tasks further. Although most objective can be represented as flat list of tasks, it is better to group related tasks under composite tasks so that there is a parent agent that do common activity for the group such as research and verify. Generally all task in the same list should be of the same altitude.
Keep graphs dynamic: on failure, consider revising instructions, canceling tasks, or decomposing tasks into composites rather than yielding to the parent. Use AgentTasks outside plan mode too when work warrants decomposition. Owners may add tasks during execution.
Generally prefer AgentTasks over directly spawned subagents.
